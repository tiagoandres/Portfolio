Una plataforma de BI para aerolíneas: de la base transaccional a decisiones diarias A BI platform for airlines: from the transactional database to daily decisions

Diseñé y construí un pipeline de datos y un dashboard analítico que hoy usan tres aerolíneas venezolanas dentro de sus backoffices. Lo que empezó como un proyecto para un cliente terminó siendo una plantilla reutilizable. I designed and built a data pipeline and an analytics dashboard that three Venezuelan airlines now use inside their back offices. What started as a single-client project became a reusable template.

02El problemaThe problem

Los sistemas de venta de las aerolíneas guardan reservas, órdenes, pasajeros y rutas en MongoDB. Es una base pensada para operar (emitir un boleto, registrar un pago), no para responder preguntas como «¿qué rutas crecieron este mes?» o «¿con cuánta anticipación compran los pasajeros internacionales?».

Los equipos comerciales dependían de exportaciones manuales y de consultas puntuales sobre la base de producción, que además eran lentas porque cada reserva es un documento grande con pasajeros, segmentos, boletos y pagos anidados.

Necesitaban tres cosas: ver el negocio a diario sin pedir reportes, armar sus propias vistas y llevar esas vistas a un PDF presentable para la gerencia.

The airlines' sales systems store bookings, orders, passengers and routes in MongoDB. It is a database built to operate (issue a ticket, record a payment), not to answer questions such as "which routes grew this month?" or "how far ahead do international passengers book?".

Commercial teams relied on manual exports and ad-hoc queries against the production database, which were also slow because every booking is a large document with nested passengers, segments, tickets and payments.

They needed three things: see the business daily without requesting reports, build their own views, and turn those views into a presentable PDF for management.

03La soluciónThe solution

Separé la operación del análisis: un proceso programado copia los cambios de MongoDB a PostgreSQL, una capa en SQL precalcula las métricas y el dashboard solo lee de ahí.

I separated operations from analytics: a scheduled job copies changes from MongoDB to PostgreSQL, a SQL layer precomputes the metrics, and the dashboard only reads from there.

04Decisiones técnicasTechnical decisions

Un cursor doble para no perder ni repetir documentos

A two-mode cursor so no document is lost or repeated

La primera carga avanza por _id; después, por updatedAt y _id como desempate, con un minuto de solapamiento para absorber relojes desfasados. El estado de cada colección (cursor, documentos procesados, último error) vive en una tabla propia, así que una corrida fallida retoma donde quedó.

The first load walks by _id; afterwards, by updatedAt with _id as a tie-breaker, with a one-minute overlap to absorb clock skew. Each collection's state (cursor, documents processed, last error) lives in its own table, so a failed run resumes where it stopped.

Presupuesto de tiempo y lotes a la medida de cada colección

A time budget and batch sizes tuned per collection

Cada corrida tiene un tope de 22 segundos para no chocar con el límite de la función serverless; si se acaba el tiempo, guarda el cursor y sale. Las reservas son documentos muy pesados: con lotes de 2.000 la petición superaba el límite del proxy y se cortaba, así que esa colección usa lotes de 250 y el resto, de 2.000.

Each run is capped at 22 seconds to stay under the serverless time limit; when time runs out it saves the cursor and exits. Bookings are very heavy documents: with 2,000-row batches the request exceeded the proxy limit and got cut, so that collection uses batches of 250 and the rest use 2,000.

Tolerancia a datos reales (y sucios)

Tolerance for real (and dirty) data

El mapeo acepta el mismo campo con distintos nombres (routeId, route_id, ruta). Las fechas se convierten con una función segura que devuelve nulo en vez de romper la consulta. Y encontré documentos con updatedAt en el futuro: si el cursor avanzaba hasta ahí, se saltaba para siempre todo lo legítimo, así que lo limito a la hora actual.

The mapping accepts the same field under different names (routeId, route_id, ruta). Dates go through a safe conversion that returns null instead of breaking the query. And I found documents with an updatedAt in the future: if the cursor moved there it would skip every legitimate document forever, so I clamp it to the current time.

Backfills controlados tras una migración de clúster

Controlled backfills after a cluster migration

Cuando un cliente migró MongoDB a otro clúster, algunos documentos llegaron con un updatedAt anterior al cursor y no entraban. Agregué parámetros para reiniciar una colección, sincronizar solo algunas o recorrer desde una fecha, y así recuperar los datos sin borrar nada.

When a client moved MongoDB to a new cluster, some documents arrived with an updatedAt older than the cursor and were never picked up. I added parameters to reset a collection, sync only some of them, or re-walk from a given date, recovering the data without deleting anything.

Precalcular en SQL en lugar de calcular en cada visita

Precompute in SQL instead of on every visit

Las métricas demográficas (edad, sexo, ciudad, nivel de membresía) salen de una tabla de hechos que se reconstruye cuando termina la sincronización de usuarios, con índices en las columnas de filtro. El dashboard consulta funciones SQL que ya devuelven el agregado y el período previo para la comparación.

Demographic metrics (age, sex, city, membership tier) come from a fact table rebuilt when the user sync finishes, with indexes on the filter columns. The dashboard calls SQL functions that already return the aggregate plus the previous period for comparison.

Avisar cuando los datos dejan de llegar

Warn when data stops arriving

Un día los gráficos cayeron a cero y la sincronización seguía «sin errores»: la fuente había dejado de enviar documentos. Desde entonces el dashboard compara la hora del último documento recibido con la actual y muestra un aviso de frescura, para que nadie lea un cero como una caída de ventas.

One day the charts dropped to zero while the sync reported "no errors": the source had stopped sending documents. Since then the dashboard compares the time of the last document received with the current time and shows a freshness warning, so nobody reads a zero as a sales drop.

Un PDF que se dibuja, no que se fotografía

A PDF that is drawn, not photographed

La primera versión capturaba la pantalla de cada bloque: salían controles de edición dentro de las imágenes, tarjetas cortadas y páginas vacías. La reescribí con un registro de bloques donde cada uno sabe dibujarse en pantalla y en PDF (texto vectorial, tablas nativas, gráficos con los mismos datos), con portada, índice y paginación.

The first version screenshotted each block: edit controls showed up inside the images, cards were cut in half and some pages came out empty. I rewrote it around a block registry where each block knows how to draw itself on screen and in the PDF (vector text, native tables, charts from the same data), with a cover, contents and pagination.

Una plantilla, tres clientes

One template, three clients

Después del primer cliente separé lo específico (credenciales, prefijo de tablas, marca, colores) de lo común (sincronización, capa analítica, bloques, PDF). Los otros dos despliegues reutilizaron esa base y solo añadieron lo propio de cada negocio, como el módulo de millas del programa de lealtad.

After the first client I separated what was specific (credentials, table prefix, brand, colours) from what was shared (sync, analytics layer, blocks, PDF). The other two deployments reused that base and only added what was unique to each business, such as the loyalty programme's miles module.

06Cómo lo construíHow I built it

Trabajé con desarrollo asistido por IA (Lovable) para escribir buena parte del código. Mi trabajo estuvo en lo que la herramienta no decide sola: qué preguntas debía responder el dashboard, cómo modelar los datos, qué calcular en SQL y qué en la interfaz, y sobre todo verificar que cada número cuadrara con consultas directas a la fuente.

Esa verificación fue la parte más larga. Cuando una cifra no coincidía con MongoDB, la causa casi nunca era el gráfico: era una definición (qué cuenta como reserva «emitida», en qué zona horaria cae un día) o un dato de origen inesperado.

I used AI-assisted development (Lovable) to write much of the code. My work was in what the tool does not decide on its own: which questions the dashboard had to answer, how to model the data, what to compute in SQL versus the interface, and above all verifying that every number reconciled with direct queries to the source.

That verification took the longest. When a figure didn't match MongoDB, the cause was almost never the chart: it was a definition (what counts as an "issued" booking, which time zone a day falls in) or unexpected source data.

07Qué haría a continuaciónWhat I would do next

  • Autenticación y permisos por rol del lado del servidor, para que cada área vea solo sus datos.
  • Server-side authentication and role-based permissions, so each team only sees its own data.
  • Pruebas automáticas de conciliación que comparen los totales diarios con la fuente y alerten si se separan.
  • Automated reconciliation tests that compare daily totals with the source and alert when they drift.
  • Extraer la plantilla a un paquete con configuración por cliente, en vez de copiar el proyecto.
  • Extract the template into a package with per-client configuration, instead of copying the project.

—Sobre la demoAbout the demo

Por confidencialidad, los clientes se mantienen anónimos y la demo usa una aerolínea ficticia con datos sintéticos generados con una semilla fija: dos años de reservas, pasajeros y millas con estacionalidad, crecimiento y adopción de la app. Reproduce las vistas, los filtros, la vista personalizada y el motor de PDF. No incluye el backend: las agregaciones que en producción hace SQL aquí se calculan en el navegador, y el panel de sincronización es una simulación.

For confidentiality the clients remain anonymous and the demo uses a fictional airline with synthetic data generated from a fixed seed: two years of bookings, passengers and miles with seasonality, growth and app adoption. It reproduces the views, filters, custom view and PDF engine. It does not include the backend: the aggregations SQL performs in production are computed in the browser here, and the sync panel is a simulation.
